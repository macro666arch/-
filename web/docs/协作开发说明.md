# 协作开发说明

## 解压后的第一次启动

需要 Node.js 20 或更新版本。

```powershell
npm ci
npm run dev
```

浏览器打开 <http://localhost:3000>。

协作包内的 `.env.local` 使用本地演示模式，不依赖后端：

```dotenv
NEXT_PUBLIC_USE_MOCK=true
NEXT_PUBLIC_API_BASE=http://localhost:3001
```

如果没有 `.env.local`，复制模板即可：

```powershell
Copy-Item .env.example .env.local
```

## 多人协作方式

建议使用私有 Git 仓库协作，不要长期通过聊天软件反复发送压缩包。

首次建立仓库后，每位成员执行：

```powershell
git clone <私有仓库地址>
cd 前端-cuc-site
npm ci
npm run dev
```

每次开始工作前拉取最新代码：

```powershell
git pull
```

提交前至少运行：

```powershell
npx tsc --noEmit --incremental false
npm run build
```

不要提交以下内容：

- `node_modules/`
- `.next/`
- `.npm-cache/`
- `.browser-test/`
- `.env.local`
- `*.log`

## 推荐分工边界

- 甲：后端接口、知识库更新、数据源核验。
- 乙：问答策略、测试集扩充、智能体编排与评测。
- 丙：前端页面、交互流程、移动端适配和演示验收。
- 丁：调研、材料整理、答辩文档、视频脚本和用户测试。

修改共享文件前先在群里说明，合并时由一人统一运行构建和核心交互验收。

## 比赛演示口径

当前默认为本地确定性演示，不依赖后端。以下能力尚未完成，答辩时不要声称已经上线：

- 后台自动巡检和定时推送
- 跨设备多人实时同步
- 真实微信或飞书机器人接入
- 独立部署的多智能体服务

完整能力、限制和测试结果见项目根目录的 `README.md` 与 `docs/测试报告.md`。

## 部署前必须处理

当前依赖中的 `next@15.1.4` 在安装时会被 npm 标记为存在安全漏洞
`CVE-2025-66478`。本地断网演示可以继续使用，但不要把当前版本直接暴露到公网。

正式部署前应升级到受支持的修复版本，并重新执行：

```powershell
npm ci
npx tsc --noEmit --incremental false
npm run build
node scripts/test56.mjs
```
