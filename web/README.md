# 中传校园信息助手 · 前端

> Next.js 15 前端：可信问答、官方证据、可执行办事卡和本机任务看板。  
> 参赛作品，非中国传媒大学官方产品。

## 产品重心

这个前端不只展示聊天答案，而是把校园信息走成一条闭环：

`查信息 → 办事卡 → 加入任务 → 截止提醒 → 错过补救`

每条回答都必须落在三种状态之一：

| 状态 | 含义 | 硬性要求 |
|---|---|---|
| **有依据** `answered` | 知识库有官方原文支撑 | 必须附官方来源，URL 在官方白名单内 |
| **信息冲突** `conflict` | 官方资料互相矛盾 | 必须并列展示至少两个说法，不得替官方裁决 |
| **无法确认** `unconfirmed` | 原文缺字段或超出范围 | 必须给出核实渠道，不能只说“不知道” |

## 已经完成的能力

- 工作台式首页：问题入口、任务概览、近期节点、材料画像、资料捷径和产品边界同屏呈现
- 三态问答与反幻觉边界
- 多轮追问：能接住“那要带什么材料”“截止呢”“电话呢”等省略式追问
- 官方来源、发布日期、原文摘录和核验状态
- 办事卡：截止时间、部门、电话、地点、材料、入口、步骤
- 个性化材料清单：按本科生 / 研究生、首次 / 补办 / 普通、本人 / 委托、线上 / 现场生成，并区分官网明确、系统整理和待核实
- 官方原文步骤与系统整理步骤分层
- 截止日期雷达：未来节点、历史节点、待核实节点分开呈现，可加入任务或导出日历
- 本机任务持久化、步骤勾选、材料勾选、甲乙丙丁分工、交接说明和动态记录
- 复制微信 / 飞书可粘贴摘要，生成带提前 24 小时提醒的 `.ics`
- 飞书群手动推送：调用 `/api/integrations/feishu/task` 发送结构化任务摘要，明确区分 `sent` / `not_configured` / `provider_error`
- 问卷闭环页：公开列出 5 项已解决、3 项部分解决、5 项仍未解决
- `/test` 56 题现场复跑

当前已完成的是用户手动触发的飞书单向推送，真实 Webhook 只由后端通过 `FEISHU_WEBHOOK_URL` 配置。尚未实现飞书群内自动问答 / 双向机器人、后台自动监控、跨设备实时同步和多智能体独立服务；界面不会把单向推送描述成双向机器人或持续监控。

## 本地运行

```powershell
npm install
npm run dev
```

打开 <http://localhost:3000>。

当前 `.env.local` 默认走本地确定性数据，答辩时不依赖后端。若要接真实 API：

```dotenv
# .env.local
NEXT_PUBLIC_USE_MOCK=false
NEXT_PUBLIC_API_BASE=http://localhost:3001
```

然后停止开发服务，重新执行 `npm run build`。不要在生产构建和开发服务并行时共用 `.next` 目录。

## 已知限制

- 数据是阶段性快照，官网更新后需要复核。
- 不查询个人成绩、课表、审批进度等登录后数据。
- 不回答其他学校或校外机构政策。
- 任务只保存在当前浏览器，换设备不同步。
- 官网巡检由用户按需触发，没有后台自动监控。
- 飞书推送由用户手动触发，只在后端配置真实 Webhook 后发送；当前没有群内事件回调或自动回复。
- 9 份问卷是同质样本，只能作为方向证据，不能代表全校。
- 56 题为团队自测，不是独立第三方评测。
